## 4. Aturan menjaga baseline

1. Setiap stage: jalankan full suite dan catat jumlah passed/assertions di sini atau di log stage.
2. Test baru bersifat additive; jangan mengubah assertion test lama untuk membuat suite hijau.
3. Test untuk perilaku finding yang masih OPEN ditulis bersamaan dengan fix-nya, bukan lebih awal (test merah menodai baseline).
4. Test yang gagal setelah patch dianggap bukti (bug test atau temuan produksi); jangan "diperbaiki" dengan melonggarkan assertion.

## 5. Catatan operasional

- **Deploy Stage 0-B: semua user login ulang sekali.** Setelah patch Stage 0-B, semua JWT yang terbit sebelum patch (tanpa claim `pwd`) ditolak dengan 401. Setiap user perlu login ulang satu kali saat deploy; umumkan ke tim dan FE sebelum rilis.
- **Status batch import bisa bernilai `failed`.** Sejak F-38 (job dihapus) status itu ditulis langsung oleh `TeacherImportController::import()` dan `StudentImportController::commit()` bila `commit()` melempar exception; batch yang sukses `done`. Nilai `processing` hanya tersisa bila proses PHP terbunuh di tengah request (mis. timeout). Nilai status ini belum didokumentasikan di SoT (kolom `import_batches.status` adalah string bebas); pendokumentasiannya perlu diputuskan terpisah.
- **Rotasi `APP_KEY` mencabut semua sesi.** Claim `pwd` dihitung dengan HMAC yang memakai `APP_KEY` (`User::passwordFingerprint()`). Mengganti `APP_KEY` mengubah sidik jari semua user, sehingga semua JWT aktif ditolak 401 dan semua user harus login ulang. Jadwalkan rotasi seperti rilis Stage 0-B dan umumkan ke tim dan FE.
- **Menulis ulang `users.password` mencabut sesi user itu.** Sidik jari `pwd` diturunkan dari hash password, jadi setiap penulisan hash baru (change/reset password, atau rehash otomatis bila kelak diaktifkan; saat ini tidak ada rehash di kode) membuat semua token lama user tersebut ditolak 401.

- **Deploy Stage 3: dua migration baru, cek data duplikat dulu.** `2026_10_04_100000_add_active_rombel_unique_to_teacher_class_assignments` (F-18, partial unique index `uq_tca_one_active_per_rombel_year`) dan `2026_10_04_100100_add_unique_to_schools_name` (F-11, constraint `schools_name_unique`). Keduanya memeriksa data existing lebih dulu dan berhenti dengan `RuntimeException` berisi daftar duplikat bila ada; tidak ada data yang diubah otomatis. Query cek manual sebelum `php artisan migrate`: `SELECT rombel_id, academic_year_id, COUNT(*) FROM teacher_class_assignments WHERE is_active GROUP BY 1,2 HAVING COUNT(*) > 1;` dan `SELECT name, COUNT(*) FROM schools GROUP BY name HAVING COUNT(*) > 1;`. Keduanya harus kosong.
- **Kode error baru Stage 3 (belum ada di katalog API Contract):** `academic_year_activation_conflict` (409), `rombel_already_has_active_teacher` (409), `assignment_inactive_readonly` (409), `rombel_field_locked` (409). Koordinasikan dengan FE sebelum rilis. `teacher_already_has_active_assignment` tidak berubah.
- **Perubahan perilaku yang terlihat FE (Stage 3):** `GET /rombels` untuk Teacher kini hanya berisi Rombel dari active assignment miliknya (kosong bila tidak ada) dan `GET /rombels/{id}` di luar scope itu 404; PATCH Rombel yang sudah punya assignment ditolak 409 bila mengubah `academic_year_id`/`grade_level`; PATCH assignment inactive ditolak 409.

- **Deploy Stage 4A: satu migration baru, tanpa risiko data.** `2026_10_04_110000_make_audit_logs_target_user_id_nullable` (F-31) hanya melonggarkan `audit_logs.target_user_id` menjadi nullable; data tidak berubah, dilewati bila tabel `audit_logs` tidak ada (infrastruktur opsional). Rollback berhenti dengan pesan jelas bila sudah ada baris tanpa target.
- **Kode error baru Stage 4A (belum ada di katalog API Contract):** `import_file_unparseable` (422, file tidak bisa dibaca) dan `import_header_invalid` (422, kolom wajib hilang di header; `details[]` memuat kolom yang hilang) pada `POST /teachers/import` dan `/student-imports/preview|commit`; `duplicate_in_file` (code per baris di `errors[]` response 200, bukan status HTTP). Koordinasikan dengan FE.
- **Perubahan perilaku yang terlihat FE (Stage 4A):** file `.xls` kini ditolak 422 `validation_failed` (Teacher dan Student import); header kolom wajib yang hilang atau salah ketik kini 422 struktural alih-alih 200 dengan error `required` per baris; NIP/NISN/nama dari Excel kini di-trim; `dashboard/teacher` tidak lagi menghitung Student yang sudah pindah Rombel sebagai inactive/graduated di Rombel lama.

- **Deploy F-38: import kini berjalan di dalam request HTTP.** Job `ProcessTeacherImportJob`/`ProcessStudentImportJob` dan trait `ActsAsActiveBatchOwner`/`ClosesFailedImportBatch` dihapus; tidak ada lagi `ShouldQueue` di `app/`. Config queue (`config/queue.php`, migration `jobs`, `QUEUE_CONNECTION` di `.env.example`) sengaja tidak diubah karena bawaan framework, bukan khusus import. Worker `queue:work` tidak lagi diperlukan untuk import.
- **Waktu respons F-38 — TERUKUR (Stage 6): import sinkron lambat, keputusan pemilik DIBUTUHKAN sebelum deploy.** Diukur lewat Postman 10.14 dan 14.01 di lingkungan dev lokal Windows (`php artisan serve`; `BCRYPT_ROUNDS` belum dicatat): **101 baris = 60,9 dtk; 1.000 baris = 577,5 dtk (9 mnt 37 dtk)**, sekitar 0,58 dtk per baris dan linear (lebih lambat dari estimasi awal 0,2–0,3 dtk). Dengan `max_execution_time` PHP-FPM bawaan 30 dtk dan timeout nginx umumnya 60 dtk, 101 baris sudah melampaui batas bawaan dan 1.000 baris tidak layak sinkron. Bila terpotong, sebagian baris sudah tersimpan (tiap baris punya transaksi sendiri) dan batch tertahan `processing`. Belum dipastikan apakah biaya dominan ada di hash password atau di query; langkah pengukurannya ada di `docs/postman/TEST-002-manual-checks.md` §3 (jalankan ulang 10.14 dengan `BCRYPT_ROUNDS=4` sementara dan bandingkan). **Keputusan pemilik (opsi: naikkan timeout khusus dua endpoint dan turunkan batas baris):** batas baris 1.000 → **200** (`App\Services\Import\ImportService::MAX_ROWS`) dan timeout endpoint import 180 dtk (nginx `fastcgi_read_timeout 180s`, `max_execution_time=180` via `fastcgi_param PHP_VALUE` di blok location dua path itu, bukan `php.ini` global). Dasar: 200 baris x ~0,6 dtk ≈ 120 dtk; timeout 90 atau 120 dtk tidak cukup. Konfigurasi lengkap dan lapisan lain yang bisa memotong (CDN/load balancer, mis. Cloudflare ±100 dtk) di `docs/ops/import-timeout.md`. Konfigurasi server ini BELUM terpasang di produksi dan belum terverifikasi (lihat §16).

- **Perubahan shape response F-15/F-10 (terlihat FE, breaking untuk klien yang memakai list tanpa paginasi):** enam endpoint GET list (`/schools`, `/headmasters`, `/teachers`, `/academic-years`, `/rombels`, `/teacher-class-assignments`) kini mengembalikan `{"data": [...], "meta": {"page", "per_page", "total", "total_pages"}}` dan HANYA `per_page` (default 20) item per halaman. FE yang sebelumnya mengandalkan "semua data dalam satu response" (dropdown tahun ajaran, daftar rombel, daftar guru) harus meminta `?per_page=100` atau menelusuri halaman. `per_page > 100`, `per_page < 1`, `page < 1`, atau non-integer menghasilkan 422 `validation_failed`. Urutan list kini eksplisit `id` ASC. Koordinasikan dengan FE sebelum rilis.

- **Kode error baru F-53 (belum ada di katalog API Contract):** `nisn_conflicts_with_staff_username` (422; `error.details[0].field = nisn`) pada `POST /students` dan sebagai error per baris (`field: nisn`) pada `POST /student-imports/commit`. Koordinasikan dengan FE.
- **Perilaku yang terlihat FE (F-53):** NISN yang sama dengan username Super Admin, atau NIP Headmaster/Teacher, kini 422 (sebelumnya 500). NISN yang sama dengan NISN Student lain tetap di-reuse (201), tidak berubah. `POST /student-imports/preview` tidak mendeteksi bentrok ini (preview hanya validasi struktural); bentrok baru muncul saat commit.
