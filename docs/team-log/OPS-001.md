## Keputusan tim (dari instruksi, dicatat di sini dan di runbook)

1. Hook `BACKUP_OFFSITE_CMD` disediakan; **lokasi di luar server diputuskan di DEPLOYMENT-001**.
2. **Restore adalah jalur rollback utama**; `migrate:rollback --step=N` hanya untuk batch yang seluruhnya alter-only.
3. Skrip pendukung di luar daftar file fokus (`smoke-test.sh`, `test-partial-unique-concurrency.sh`) diizinkan karena dibutuhkan AC.
4. Versi PostgreSQL produksi belum ditentukan; runbook mewajibkan versi klien `pg_restore` sama atau lebih baru dari `pg_dump` dan klien mengikuti server produksi. **Versi lokal tim belum diisi** (pesan tugas berisi placeholder "[isi]"); tertulis "belum diisi" di runbook.
5. File backup `chmod 600` cukup untuk sekarang; **enkripsi dicatat sebagai keputusan DEPLOYMENT-001, tidak diimplementasikan**.

## Temuan yang perlu diketahui

- **Rollback create-table bisa menghasilkan data keliru tanpa error.** Setelah rollback + migrate ulang `gamification_levels`, `GET /gamification/me` dan dashboard student tetap HTTP 200 tetapi `gamification_level` menjadi 0 (seharusnya 4). Ini dasar keputusan 2.
- **`GET /up` tetap 200 saat `php artisan down`**; API 503. `/up` bukan penanda maintenance selesai.
- **Pasca-restore:** token yang password-nya berubah setelah backup → 401; token terbit sebelum backup tetap valid; aktivitas setelah backup hilang; `cache:clear` wajib. Terbukti di E2.
- **Lingkungan test:** `.env` berbasis `.env.example` (`APP_URL=https://…`) membuat 2 test `EnforceHttpsTest` gagal; dengan `APP_URL=http://localhost` suite 518 passed / 2814 assertions (cocok baseline). Bukan bug kode; dicatat di runbook bagian 9.
- **HEAD zip `afa658c`** berbeda dari yang disebut pesan tugas (`85d8b27`, 515 passed); baseline §18 untuk `afa658c` = 518/2814.
- `php artisan test` memakai `RefreshDatabase` dan menghapus isi database yang dipakai: selalu gunakan database terpisah.

**Riwayat kegagalan:**
1. Kegagalan pertama yang dilaporkan (`pg_dump v14` lebih lama dari server v17) berasal dari percobaan Orang 1; di komputer pemilik tidak ada server 17 (hanya 14.5 dan 14.24). Pengaman versi tidak diubah. Untuk menguji server 17.11, klien 17.11 dan server 17.11 sementara (port 5434, folder data sendiri) dijalankan dari zip binaries tanpa menyentuh Laragon atau server 14.
2. `backup.sh` gagal di Git Bash: `invalid snapshot identifier` karena `psql.exe` menulis `\r\n` ke pipa dan nilai snapshot dari `coproc` membawa `\r` (BUG-1). Terbukti dengan `od -c` (`x \r \n` tanpa pembungkus, `x \n` dengan pembungkus). Uji dilanjutkan dengan pembungkus `psql` di luar repo yang membuang `\r`.

**Temuan:** BUG-1 (khusus Windows); NEEDS DECISION: dukungan Windows native (patch minimal terpisah) atau skrip hanya untuk Linux/WSL, dan versi PostgreSQL "lokal tim"; DOKUMENTASI: runbook menulis PHP ≥ 8.2 padahal `composer.lock` efektif mensyaratkan 8.3 (belum diubah); TECHNICAL NOTE: tidak ada perbedaan perilaku PostgreSQL 16.15 vs 17.11 yang terlihat.
